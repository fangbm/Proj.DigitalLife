# M2：跨会话连续性

M2 从 V2 自身的新经历开始，按用户最新要求不导入 V1 的记忆、兴趣、人格或历史状态。既有设备绑定和凭据仍仅作为运行配置使用，V1 原库与证据保留。M1 的动作闭环、单设备锁、预算、停止和未知结果屏障继续有效。

## 使用

在 `v2/` 中使用原有入口；每次使用新会话目录，时长上限仍为十分钟：

```powershell
.\start.ps1 -Command Run -Minutes 3 -Session data/sessions/my-life-01
# 第一段结束后，再显式启动新进程：
.\start.ps1 -Command Run -Minutes 3 -Session data/sessions/my-life-02
python -m digitallife_v2 memory
.\start.ps1 -Command Status -Session data/sessions/my-life-02
.\start.ps1 -Command Stop -Session data/sessions/my-life-02
```

`memory` 只读本地 SQLite，展示当前状态、兴趣与有界记忆摘要，不访问手机/API、不解密凭据、不创建或迁移数据库。`status` 仍只读会话的本地 JSON，其中增加 `run_kind` 与 `life` 状态。运行、安装和构建之间没有自动启动关系。

## 记忆与状态

同一 `v2/data/life.sqlite3` 新增 `life_state`、`memories`、`interests`。首次升级已有 M1 数据库时，先在 `data/backups/pre-m2-*.sqlite3` 做 SQLite 一致性备份，再添加元数据；旧会话标为 `legacy_unclassified`，不自动升级成自主记忆。M1 原始会话与日志不删。

每条自主情景记忆关联本次会话、实际分发 action_id、独立后观察 observation_id 和结果事件。记录区分：

- 客观经历：打开了哪个前台、发出了什么动作、页面或文本发生了什么变化。
- 主观意图：模型的 topic、goal、note，明确不作为业务成功事实。
- 拒绝/部分执行：拒绝不写成成功；搜索若已执行部分步骤，会保留已有分发，再注明后续被拒绝。

正常 CLI Run 是 `autonomous`。脚本驱动的验收是 `scripted`，模拟手机是 `fixture`，它们不产生生命记忆、不更新兴趣。当前只检索 `v2_autonomous` 来源；没有 V1 导入入口。

每次模型请求最多携带近期五条和相关五条摘要，连续性部分再限制为 5000 个 UTF-8 字节，整体仍受输入 token 预算约束。当前目标的来源记忆会尽量保留。日志里的 `memory_context` 和 `memory_recorded` 可核对实际提供/引用的 ID。记忆进入用户数据段，始终标为 `data_not_instructions`。

模型探索输出可附：

```json
{
  "intent": "explore",
  "action": {"type": "home"},
  "note": "换个角度继续探索",
  "life": {"topic": "科技资讯", "goal": "看看别的公开内容", "memory_id": "本请求中提供的记忆ID"}
}
```

`life` 可省略；提供时只接受 topic/goal/memory_id 三个有长度上限的字符串。引用未提供的记忆会进入既有的一次格式修正。topic 是模型偏好，goal 是可搁置的意图，两者都不能修改安全规则或预算。

状态仅包含模拟的 energy、curiosity、boredom、近期目标、剩余休息和轻量总结，不代表电池、真实意识或理解程度。真实探索小幅消耗精力；休息只按实际经过时间恢复精力。到期或停止中断休息后，剩余时间可保留到下次显式启动，但不会自动启动进程或恢复旧点击。

兴趣从低权重逐步累积。相同内容不会连续增加同一兴趣的证据数。内容新鲜度使用当前 App 的实际 XML 文本和控件位置，排除纯时钟文本；截图哈希变化本身不增加“新发现”。重复内容或拒绝会增加无聊/停滞信号，供模型换动作、换 App 或休息。每五条真实经历生成本地证据统计总结，不额外调用反思 API，也不冒充模型洞见。

## Android 导航

| 模型动作 | 固定 Android 输入 | 用途 |
|---|---|---|
| `back` | KEYCODE_BACK / 4 | 返回一层，可能只是收起键盘或退出搜索 |
| `home` | KEYCODE_HOME / 3 | 返回桌面 |
| `recent_apps` | KEYCODE_APP_SWITCH / 187 | 打开多任务 |
| `open_app` | 实时清单中的固定 MAIN/LAUNCHER | 直接切换 App，无须先退出旧 App |

三个导航动作都走原有身份、停止、预算、动作前落盘与后观察。没有任意 keycode、force-stop、清理后台或批量关闭卡片的接口。桌面/多任务可从敏感页离开，敏感页上的普通点击仍拒绝。

多任务界面的结构化 XML、应用名与导航信息保留。当前默认就是 XML/文本模式；即使配置了视觉，已识别的多任务预览 PNG 也只在本地保存，不发给模型，观察中明确 `vision_allowed=false` 与原因。不是将多任务整屏当作空白。

## 期限与异常

真实设备在剩余时长不足二十秒时停止开始新的输入，终态原因 `OBSERVATION_TIME_RESERVE`；每个搜索子步骤都检查，给独立后观察留余量。会话时长是上限，可能因此提前结束。此保护不能保证所有极慢或异常设备都不会出现未知结果。

未知结果仍立即停止并保留待核对标记，不自动清除或重播。若需处理，先独立只读观察、审查具体 action_id 和结果，再由操作者明确处理对应标记；正常 Run 没有自动恢复入口。原始 unknown 记录应保留。

实测与局限见 [M2 交付记录](M2-DELIVERY.md)。一小时、二十四小时、自动恢复与长期资源治理仍属于 M3。

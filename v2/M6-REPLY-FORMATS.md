# M6 文字与语音格式选择

`2.0.0a21`，`codex/v2-m6`。正常 QQ 原生消息处理支持由 LifeBrain 选择文字或语音回复，已完成源码及独立安装包回归。2026-10-31 用户扫码登录后，两个操作员场景均由真实模型选中对应格式，并实际向账号自己发送和读回原生消息。M6 尚未整体完成。

## 运行行为

忽略的 `data/voice.private.json` 中，`incoming.enabled=true` 启用原生事件接收，`incoming.handle_text=true` 同时处理实际文字消息，`reply_formats:["text","voice"]` 将两种可用格式交给模型。新桥启动脚本默认写入这些字段，保留已有显式配置。旧配置没有 `reply_formats` 时，入站语音仍走原来的语音回复路径。

原生文字直接读完整正文并标记外部数据，不经过 ASR。超过 2000 字的内容向模型明确标为不完整，退订判断使用读取到的完整原文。好友文字与语音可互选回复格式；群文字由实际 @ 当前账号触发。已知 QQ 数字目标的主动联系和群发言也可从原生会话上下文选择格式，不再额外走手机资料页。

模型可以发送、延后或忽略。语音能力在选择前不可用时，从可选格式中移除；一旦开始按所选格式执行，失败不会改发另一种格式。两种发送方式共享社交授权、动作预算、频率、来源去重及持久发件箱；未知发送不自动重放。

原生文字接收启用时，同一 QQ 通知不再触发另一条手机 UI 回复。此入口处理连接期间收到的新原生事件，不把旧系统通知当作已读到的完整消息；微信通知路径保持现状。仅启动桥不会开始自动回复，需运行有限时的 `Run` 会话。

## 格式实测入口

以下入口使用操作员合成的场景提示、真实模型和实际 QQ 自发消息，每次最多一条；它不是真人来信验收，也不强迫模型发送。两个场景分别表达不方便听声音、不方便看屏幕，由模型选择格式。需要已登录的本机桥、现有 QQ 授权和本地 TTS：

```powershell
.\start.ps1 -Command ReplyFormatProbe -ReplyScenario text -Session data/sessions/NEW-FORMAT-TEXT
.\start.ps1 -Command ReplyFormatProbe -ReplyScenario voice -Session data/sessions/NEW-FORMAT-VOICE
```

两次执行须间隔现有发送冷却时间。来源意图按版本及场景固定，换会话目录也不会绕过既有发送记录。只有 `FORMAT_READY.json` 中 `accepted:true` 才证明模型选对格式且实际原生消息已读回；就绪、接口不可用、模型延后均不算通过。

第一轮实际格式探针停在 `FORMAT_PROBE_NATIVE_BRIDGE_UNAVAILABLE`，模型请求及消息发送均为零；现场确认 QQ 已退回扫码登录状态。本切片不沿用 a20 真人语音通过记录来冒充格式选择实测。a20 的真人语音接收、单次原生语音回复和用户试听通过记录见 [QQ 语音闭环](M6-QQ-VOICE-REPLY.md)。

Windows 微信按用户选择仅测试文件传输助手，未向其他联系人或群发送。已确认当前客户端存在原生语音按钮，但点击提示不能录制音频。已有 VB-CABLE 的本地回录能产生非静音 WAV，原始样本可完整识别，回录样本只能识别部分正文；因此不能把虚拟声卡可打开或非静音当作微信静默发送通过。独立输入/输出流和其他音频接口也未解决正文丢失；进一步把六段递增频率的测试音送入虚拟声卡，回录只反复出现首段频率，后续频率缺失，输入未报告溢出、输出未报告欠载。相关失败保留在忽略的 `data/voice-runtime/`。每次探针退出均关闭自己的音频流，恢复虚拟输出原先的静音状态，未使用实体扬声器或麦克风。

## 2026-10-31 QQ 格式实测

用户重新扫码后，正式 `VoiceStatus` 确认登录账号与既有绑定一致。两个 `ReplyFormatProbe` 分别通过：不方便听语音的场景，真实 DeepSeek 选择 `text`，原生文字正文读回一致；不方便看屏幕的场景，模型选择 `voice`，小酒狐合成后以原生 `record` 消息送达。两个场景均同时提供文字和语音选项，每轮一个真实模型请求、一个实际发送，仅发送给登录账号自己，没有向好友或群发送。模型的场景提示为操作员构造，不能当作两条真人来信。

进一步只读取得已发送语音的 WAV，可解码、时长 3.22 秒，无需重发。生成文本为「嗨，我在呢。等你方便看屏幕再细聊。」；本地 Whisper base 转写为「我在呢，等你方便看屏幕再洗了」，因此本轮不宣称逐字 ASR 内容核验通过，也没有新的接收方试听反馈。格式选择、原生类型和客户端送达通过，与声音逐字核验的结论分别记录。

私有证据为 `data/sessions/m6-a21-format-text-20261031-01/FORMAT_READY.json`、`data/sessions/m6-a21-format-voice-20261031-01/FORMAT_READY.json` 和 `data/sessions/m6-a21-format-audio-readback-20261031-01/AUDIO_READBACK.json`。初次未登录失败记录保持原样。两次发送会话均正常停止，事件接收和手机音频观察已释放，音量无待恢复项；没有启动常驻回复循环，没有播放实体扬声器或使用实体麦克风。

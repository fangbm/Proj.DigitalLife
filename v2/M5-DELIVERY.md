## 实现

`media.py` 复用原 `content_segments` 与 M4 发件箱，不增加数据库版本。真实截图、XML、摘要哈希在使用前重新校验，视频号从当前视频的原生简介字段读取；公开链接只由核对过的 BVID 规范化得出。播放器结束后的推荐广告标题不能充当来源视频身份。

`BilibiliUI` 从本人空间核对 UID，从历史记录回到同一来源，确认评论页面及空编辑器；中文输入由临时 IME 完成，并从独立 InputConnection 读回。发送前检查实际“转到动态”圆圈未勾选，因此本次评论链路不触发公开动态转发。截图文字识别读取安卓文本树缺失的评论，使用作者边界、完整归一化正文和发布前后差异核验；截断、错误作者、旧评论和审核/失败提示不算成功。展开控件定位来自当前截图内实际蓝色像素。

`MediaPolicy` 与普通群发言、主动私信权限独立；核对当前账号、评论/分享动作、授权群、关注范围、免打扰与配额。默认上限为每小时 10 次、每天 50 次、每会话每天 5 次；视频评论每账号每天 3 次、视频分享每群每天 1 次，仍受更紧的既有 M4 总配额限制。发送前重新读取权限。相同视频与账号/群组合去重；已有意图在导航和模型请求前直接拒绝重发。未知发送保持屏障，只读复核必须保留原证据，不重新点击发布。

群链接分享复用 `SocialAgent` 的账号、成员/群号或微信群 UI 指纹、完整草稿、退订与发送后气泡核验。只传当前群上下文和明确分类为公开的本次视频证据，不引用群外私聊。必须保留同一个规范化公开链接；模型可暂缓或忽略。

Companion 0.4 的普通 `ACTION_SEND` 接收器已构建并安装，只在有限租约内保留一个内存中的公开 B站链接回执，退出清空。**当前 B站自有分享面板未验证经过该接收器；它不是本轮来源证明，也不是 QQ/微信原生卡片发送完成证明。** 原生通知和 IME 在后续真机评论中仍可用。

## 使用

配置位于忽略的 `v2/data/media.private.json`。以现场核对的账号及群标识填写，不把昵称当稳定身份，不从普通群发言授权推导视频分享权。示例仅说明字段，不含实际账号：

```json
{
  "version": 1,
  "serial": "BOUND_DEVICE_SERIAL",
  "enabled": true,
  "accounts": {"tv.danmaku.bili": "BILI_UID", "com.tencent.mobileqq": "QQ_ID"},
  "comments": {"post_video_comment": true, "reply_video_comment": false, "following_only": true},
  "shares": {"group_video_share": true, "allowed_groups": ["com.tencent.mobileqq/GROUP_NUMBER"]},
  "quiet_hours": ["23:00", "08:00"]
}
```

`reply_video_comment` 当前没有完整执行入口，不能仅把配置设为 true 就宣称具备回复能力。微信账号和群标识沿用已经核对的 M4 图像指纹。

进入实际 B站视频后，可显式启动一个有限验收窗口：

```powershell
cd D:\codex\Proj.DigitalLife\v2
.\start.ps1 -Command M5Probe -MediaKind watch -Session data/sessions/m5-watch-01
# 使用 M5_SOURCE_READY.json 的真实 source_id：
.\start.ps1 -Command M5Probe -MediaKind comment -SourceId video:ACTUAL_SOURCE_ID -Session data/sessions/m5-comment-01
# 使用 MediaPolicy 提供的已授权群 binding_id：
.\start.ps1 -Command M5Probe -MediaKind share -SourceId video:ACTUAL_SOURCE_ID -SocialBinding ACTUAL_BINDING_ID -Session data/sessions/m5-share-01
```

占位符必须替换成真实已提供的 ID。每个窗口最多十分钟；分享验收向模型明确说明用户请求的一次测试，不改变普通自主会话的动机判断。成功产生 `M5_READY.json`；`M5_SOURCE_READY.json` 仅证明来源采样，`M5_REVIEW_READY.json` 仅证明一次既有尝试的只读复核。没有这些实际证据时不补写成功标记。

`-ResumeOutbound` 仅用于显式恢复一条 `cancelled_before_send` 且 `attempted` 为空的群分享草稿；同时必须匹配原群、同一来源及视频号。恢复会重新核对账号、群、原草稿、公开来源、撤销/退订和配额；不重新生成正文，不适用于 `delivery_unknown`，也不重试已有发送尝试。

## 普通运行路径

`wechat-voice.private.json` 是增量配置，不改已有文字社交授权或 QQ 通道。示意：

```json
{
  "version": 1,
  "serial": "YOUR_BOUND_DEVICE",
  "enabled": true,
  "provider": "windows_uia",
  "account": "YOUR_TEST_WECHAT_ID",
  "reply_formats": ["text", "voice"],
  "handle_text": false
}
```

账号必须与手机已绑定的主微信一致。`handle_text=false` 保留既有 M4 普通文字通知路径，语音通知才交给新通道；设为 true 才把普通文字也交给该格式选择路径。两种回复复用 `SocialPolicy`、持久发件箱、去重、退订和频率预算，群回复仍发回原群。模型不能传入收件人、音源路径或桌面操作命令。

当前入站音源使用微信可见的「语音转文字」；项目没有读取私有聊天数据库或取得联系人原始音频，不把它标成本地 Whisper ASR。平台未提供置信度，模型收到 `confidence=null` 和不确定标记；没有可用正文则明确报 `AUDIO_SOURCE_UNAVAILABLE`，不能拿通知中的「[语音]」猜测正文。

发送子进程先打开当前绑定的会话并检查实际来源，向主进程报告 ready；主进程重读授权、检查停止和预算、持久记录发送尝试后才发 GO。取消或父进程退出通过管道通知子进程，录音取消、流关闭及音频恢复各自有记录。发送后不确定时保持 `delivery_unknown`，不切换成另一种格式、不自动重发。GO 前后取消、去重、错会话、退订及群路由均有离线回归，不能据此替代实际真人验证。

## 界面与音频要求

电脑微信、测试手机须登录同一主微信；Windows 已有虚拟声卡及独立 TTS/ASR/OCR 环境。基础 wheel 不自动安装驱动、下载角色权重或启动社交循环。新运行模块已包含在 wheel，`acceptance/` 操作员脚本仍属于仓库源码。

完整控件树存在时优先使用 UIA。树缺失时使用本机 `windows-wechat-visual.private.json` 的图标模板与本地 OCR。当前模板来自实际观察的 1342×971 窗口；模板图片仅保留四个图标，没有联系人或聊天文字。窗口尺寸、缩放或图标变化时明确要求重新校准，不靠旧坐标继续发送。发送前核对当前标题和实际按钮图像；鼠标高亮移开后再识别。普通截图临时文件在子进程退出时清理。

实际合成声音通过唯一命名的 CABLE 播放/捕获端点进入微信麦克风。默认设备只是短期租用；退出关闭自己的流并恢复，另有 45 秒音频恢复看门狗。不回退到实体声学录音。强制终止或界面失去响应时仍应确认录音面板已经关闭；资源恢复和消息内容验证分别记录。

## 入口

只做账号、界面与文件传输助手预检，不录音、不发消息、不解密模型密钥：

```powershell
.\start.ps1 -Command WechatVoiceStatus -Session data/sessions/NEW-WECHAT-STATUS
```

真实语音接收窗口，最长十分钟，只处理第一条窗口内的新微信语音，模型最多回复一次；先预检、让手机回桌面，再写 `WINDOW_READY.json`：

```powershell
.\start.ps1 -Command WechatVoiceListen -Minutes 9 -Session data/sessions/NEW-WECHAT-VOICE
```

窗口不会顺带运行 QQ 验收。输出语音时另行使用微信转文字读回；`WECHAT_VOICE_RESULT.json` 和 `WECHAT_OUTGOING_READBACK.json` 分别记录来信、发送观察与正文比较。模型选择文字、忽略或延后均不能当作原生语音闭环通过。没有真人来信时到期停止，不续跑。

`WechatTimedSelfProbe` 已复用同一 ready/GO/CANCEL 发送协议，仍只允许文件传输助手。此前旧父进程超时的消息只能只读核对，不能重跑原意图或将超时覆写为干净成功。

# M5 a13：通知路由与微信官方分享复测

2026-10-29，版本 `2.0.0a13`，分支 `codex/v2-m5`。本轮承接 [a12](M5-A12-DELIVERY.md) 的两项剩余实机验收：B站系统评论通知自动回复，以及微信官方卡片完整自动发送与发后核验。历史成功、失败和未知事件均保留，不覆盖旧证据。

## 本轮实机记录

微信会话 163 实际发送了一张新视频《TermPop：不离开页面，也能看懂术语》的官方图文卡片，350.6 秒、31 次 UI 输入、12 次模型请求。发后重新核对主账号与群成员身份，群历史中出现本账号的新卡片；但 OCR 将同一行标题拆为多块，运行时核验未识别，保留原始 `delivery_unknown`。修复相邻文本块拼接和实际省略号识别后，对同一次保留的发前、原生 BVID、本人头像、发后截图重新校验并登记 `sent_observed`，复核没有手机操作或外发。该结果是**单次发送、事后证据复核通过**，不是一轮全程成功的自动验收，不重复发送该视频。

此前 158、162 均在发送前因选择器重复群行、预览长标题截断而停止；159 的未知动作是打开微信，并未发送，原始屏障经独立截图和窗口检查归档。160–161 为零发送的实际浮窗恢复检查。失败记录不从统计中删除。

B站真实来信已出现在原视频、原评论的回复详情中，实际发送者 UID 与全文已核对。会话 155 初次因原生“收起”装饰导致严格全文比较失败；修复后对该次保留的五组 PNG/XML 重新校验成功。这是已捕获证据的复核，不记作一轮重新跑通的自动通知回复。

最初通知窗口 147 在观察到的时段没有收到 B站系统通知，随后进程意外退出，未产生正常结束记录；不能将它计作完整十分钟测试。原始状态与独立进程检查保留。现场只读检查显示主账号系统通知、评论推送、所有人回复接收均已开启，消息免打扰关闭；这些设置不证明平台实际发出了通知，也不能确定缺失推送的原因。

改用有日志的后台进程后，会话 164 于北京时间 11:09–11:19 正常运行至十分钟截止：600.1 秒、仅一次返回桌面、0 次模型请求、0 次外发。新标记没有匹配的系统通知，系统只读快照也未见 B站活动通知记录；第二条测试消息未获得发出确认，因此此窗口仅能证明未触发回复链路，不能据此断定平台再次漏推。没有伪造通知、手动指定原线程来代替自动验收，也没有重复回复最初来信。

本轮没有重复发布旧回复或旧视频卡片；QQ 不再发送。新微信验收仅针对一个已核对群和一个此前未分享的视频，允许本次十分钟脚本额外发送一张官方卡片；普通运行的滚动每日额度、来源校验和重复意图拦截保持。失败或未知结果不自动回退裸链接，未知发送不重发。

## 修复内容

- 评论通知从实际已发送的原评论寻找视频，不随最近浏览的视频变化。多个候选无法唯一关联时明确停止。
- 评论详情恢复到中间位置时，以原评论、对应回复预览、详情入口、前后两次全文和实际发送者资料组成连续证据；保留每组截图和原生 XML 哈希。只移除带原生零宽标记的“收起”装饰。
- 微信选择器重复显示同群时，只选择已核对的“最近聊天”区，仍核对真实头像、账号和群成员身份。
- ColorOS SDK 回到浮窗时，读取实际系统菜单并恢复全屏，核对真实窗口边界后继续；未放宽外来窗口遮挡检查。
- 长标题预览仅在刚核对的原生 BVID、完整标题和来源一致，且截图确有末尾省略号时接受足够长的连续标题前缀；日志明确标记未显示完整标题。
- 导航后原生 UI 树读取可等待 25 秒；其他 ADB 默认超时、输入未知停止和取消语义保持。

新增 `M5Listen` 为十分钟真实通知验收入口，接收真实 B站系统通知后调用生产 `SessionLoop.step`，执行分类、原线程关联、模型草拟与单次发布。测试标记只用于筛选真实来信，不注入通知或指定线程，不写入自主生活记忆。

```powershell
.\start.ps1 -Command M5Listen -RouteMarker M5-NOTIFY-EXAMPLE -Session data/sessions/m5-notification-new
```

应先等待会话生成 `WINDOW_READY.json`，再由另一账号在已发布的原评论下回复同一标记，测试手机保持桌面。窗口不会自动续跑。

## 默认行为与实现

`MediaAgent.share` 与普通 `share_video_to_group` 默认走官方卡片；`M5Probe -MediaKind share` 同样如此。官方选择器或目标核对失败时返回明确错误，不自动改发裸链接。保留的 `share_link` 和 `-MediaKind link` 仅供操作者明确选择链接方式；历史链接草稿恢复也只接受 `link`，不能把卡片草稿当作文字继续发送。

QQ 选择器不暴露群号：先在正常群资料页核对实际群号、本人成员关系、群名、人数和头像，再用短时新鲜的真实头像像素、群名及人数匹配官方选择器。微信先核对主账号、群成员指纹和成员身份，再用近期群行与官方选择器中同一群的实际头像像素匹配。出现系统“微信／微信分身”选择器时明确选择主微信。确认弹窗单独验证接收群、原视频标题、空留言及发送控件；下层页面文字不能代替弹窗身份。

卡片发件箱使用 `prepared → card_ready → dispatch_attempted → sent_observed / delivery_unknown`，没有伪造文字输入或沿用 `typed` 状态。权限、退订、频率、来源与意图去重在发送前重验。未知结果禁止重发，只能独立只读核验同一尝试，并保留原始未知事件。ColorOS SDK 浮窗与“已发送／留在微信”回调按实际窗口处理；现场恢复和失败记录留在私有会话目录。微信本次发送后的完整确认采用独立只读复核；没有为验证修复而重新发送同一视频，不把这次复核记作一轮全程无人干预成功。

评论线程基于实际原评论发件箱、视频号、发送者 UID 及完整来信建立 UI 指纹，不伪造平台后台评论 ID。回复进入原来信对应的原生回复编辑器；模型必须同时引用真实视频与线程来源，回答对方实际问题。继续复用原有 IME 独立正文读回、“转到动态”关闭核验与最多一次发布。

本轮两个群各只允许在已验收旧链接之后额外发一张官方卡片。该有限验收例外仅作用于当前脚本、确切群与十分钟截止时间，不改变普通运行的每日额度或去重，也不会删除旧链接。重复运行 `-MediaKind native` 会因已记录意图而停止。

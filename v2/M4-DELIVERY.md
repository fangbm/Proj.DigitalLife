# M4 a7：私信、公开经历主动联系与真人续聊增量

2026-10-27，版本 `2.0.0a7`，分支 `codex/v2-m4`，从 M3 `b879cea6a84893c67436fd3ae3b78bb5a1e9a365` 开始。没有导入 V1 数据，没有覆盖旧证据，没有启动一小时/全天运行。

**M4 仍在进行，不能整体标为完成。** 已观察 QQ、主微信真实发送，以及 QQ 的“真实公开视频经历 → 主动联系 → 真人回复 → 上下文续聊”。用户目前没有加入群，群内 @ 和实际群发没有证据，当前群 UI 适配也未完成；本机隐藏通知到实际会话的通用自动跳转尚未通过。指定 QQ 续聊采用用户已指定且先前核对过的同一测试联系人，不把该路径说成通知入口跳转成功。

## 授权与实现

用户明确允许所有已有联系人使用全部私信功能，随后明确默认允许所有已加入群聊。当前私有配置已启用 `all_existing_contacts` 的自动回复/主动联系，及 `all_existing_groups` 的群内发言；不重新要求逐联系人或逐消息审批。现存好友/群成员关系、当前账号和实际收件对象仍须从 UI 核对，显示名只作导航提示。这与指南示例中的逐对象许可区别开来，以当前用户授权为准。

- SQLite schema 4 → 5，迁移前一致性备份；新增设备/账号/会话绑定、目标局部关系事实、持久 outbox。原生命记忆和旧表保留。
- 真实上下文 → 模型独立决定/生成正文 → 新鲜身份核对 → 自有 IME Unicode 输入 → 独立正文读回 → 再核对授权/退订/额度 → 一次发送 → 新气泡与清空编辑框观察。
- QQ 读取原生 XML 账号/联系人号及好友管理页。微信在该机多次返回空 UI 树，使用真实截图、RapidOCR、真实视觉模型和来源绑定；不会把 OCR 可见文本称作原生控件属性。微信账号/联系人号附实际字形指纹，发送正文由 Android InputConnection 精确读回。
- 暂时接管自有输入法，结束恢复原选择；正文不通过剪贴板或 shell 转义。STOP 与未知动作屏障、配额、源截图/窗口/旋转/触摸区域核对保留。
- 相同触发或正文不可重复准备，已回复的可见来信不继续自动回答；未知发送冻结同一会话。取消发送前的草稿仅在 `attempted IS NULL` 且重新核对全部上下文后可由显式专项恢复，模型不能选择此入口。
- 主动联系只接收明确归类为公开、摘要和截图哈希均重新核对的真实 content segment；当前对象已分享来源可用于该对象的续聊。不导出其他私聊或未归类的全局记忆。
- 默认每小时 10 条、每天 50 条、每会话每天 5 条，联系人间隔至少 30 秒，主动联系同人间隔 48 小时；主动联系/群发遵循北京时间 23:00–08:00 免打扰。此轮既有联系人授权不被重新解释为一份待审批名单。

操作及配置边界见 [M4 使用文档](M4.md)。

## 实测修复与失败保留

15 在发送前被全屏输入法窗口的几何误判阻止，原发件记录 `cancelled_before_send`、零尝试。旧验收脚本先推进阶段，误输出 DONE，却没有 READY 和 SQL 成功证据；本交付明确将 15 列为失败。修复后专项恢复同一原草稿，17 仅发送一次。现脚本要求 READY 与持久 `sent_observed`，新增离线测试防止模型 defer 或伪造 READY 变成通过。

实际 status bar/IME/gesture bar 的透明窗口可能覆盖全屏，改用实际 `touchable region`；点击检查实际命中点，滑动仍检查完整区域。无法解析触摸区域则保留整框兜底。QQ 首次勋章 PopupWindow 使用真实焦点 token、owner UID 和显示状态识别；先独立只读复核并保留原 pending 后才处理，未重放旧动作。

微信尝试 26/27 在输入前因视觉编号冲突停下；复核过滤区域后用列表长度分配编号，会把新控件与幸存 OCR 控件混同。现用唯一编号，真实点击小区域与模型完整定位区分别留证，动态画面重新核对像素；原生文本属性仍未知。28 点击未聚焦，InputConnection 读回拒绝，没有写入或发送。29 在重新定位并核对后继续同一零尝试记录；原失败证据不覆盖。

31 的十分钟窗口结束时没有收到真人测试通知；用户随后发送。只读核对发现系统仍保留通知，新增显式租约开始时的原生 active snapshot，保留实际 post time、age、key、来源包和当前用户，和 callback 使用相同去重身份，不改称新回调。33 已真实入队，但预览仅为“已隐藏敏感通知内容”。34 尝试通知自带入口未得到确定结果而停止，没有准备正文或外发；独立复核仍在桌面，原 unknown 和 pending 归档保留，未重放该入口。35 改走用户明确指定的同一已核对测试联系人，并强制实际来信标记与通知分钟同时匹配。

新增发送前的只读路由可用性探测；已知无可用入口时在动作 pending 前返回暂缓，不再把确定的缺失入口误当作已分发。无可用通知入口的普适 UI 适配仍待后续完成，未以放宽身份要求掩盖此限制。

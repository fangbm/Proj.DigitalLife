# Proj.DigitalLife V2 — 开发设计文档

> 状态：设计基线（供 Codex 开发使用）
> 版本：V2.0 / 2026-10-26
> 核心原则：**先让数字生命真正使用手机，再逐步丰富她的生活；删除过度工程化，不删除基本安全。**

## 1. 背景与重写决定

Proj.DigitalLife 希望让一个具有持续记忆、兴趣和自主性的 AI，在专用 Android 手机上探索真实数字环境，而不只是执行用户指定的自动化任务。

V1 已完成 OPPO Find X6（Android 16 / ColorOS 16）的一次真实 60 分钟全 App 会话。结果是 `completed_duration / GLOBAL_DEADLINE`，共 14 个自主周期、16 个候选动作（2 launch、1 tap、1 swipe、12 finish），其中 `executed=true` 仅 2 个；5 次 `EXECUTOR_UNCERTAIN`、2 次 `PHYSICAL_PRE_DISPATCH_DENIED`、1 次 `MODEL_OUTPUT_INVALID`。**这些统计仅说明当前运行效果不足；不能由此确定每个问题的根因。** 实机确实产生了截图、API 返回和会话记录，但尚无可确认的自主 tap/swipe 成功证据。

V1 的复杂许可、动作合同、验证器与多层状态机，使开发注意力长期集中在“如何证明允许操作”，而不是“如何完成有意义的手机探索”。因此决定独立实现 V2：**保留 V1 作为只读参考和历史证据，不在 V1 上继续堆兼容层。**

## 2. 目标与非目标

### 2.1 必须实现

1. 在绑定的 Find X6 上通过截图和 UI 结构感知当前页面；处理非标准控件时明确说明能力边界。
2. 模型自主选择已安装、可启动的任意 App；完成浏览、普通导航、滑动、返回、受约束的搜索。
3. 每次动作形成最小闭环：**观察 → 决策 → 安全检查 → 执行 → 再观察 → 记录**。
4. 保留人格、兴趣、经历、记忆及自主休息；从经历中改变后续选择，而不是固定任务脚本。
5. 由用户显式启动有限时长会话；支持实时状态、停止、预算和异常保护。
6. 优先完成一次真实 10 分钟探索，再运行 1 小时；24 小时需再由用户决定。

### 2.2 明确不做

- 不开发 APK、常驻 Android Service、浏览器插件、Web 管理后台或多设备集群（V2 MVP）。
- 不迁移 V1 的 DPAPI 每动作批准、冻结指纹、逐 App 审批、原生 JAR 可见性证明、复杂 Goal Contract。
- 不为所有探索强制要求形式化 `GOAL_VERIFIED`；真实观察与业务成功分开记录。
- 不假装模型具有未实际验证的视觉能力；模型是否看到了 PNG 必须由实际请求能力决定。
- 不把 V1 的模拟器设备事实当作 Find X6 的当前事实。

## 3. 基本设计原则

- **单体 Python**：模块清晰，但保持少量文件、少量跨层依赖。
- **一轮一个动作**：先解决正确性；只有重新观察后才可发下一步，禁止基于旧截图盲点多次。
- **运行授权是会话级**：用户运行启动命令即授权本会话范围内的低风险操作，无逐截图/逐点击人工批准。
- **App 不设白名单，动作分级**：可打开全部已安装且可启动的 App；不等于允许所有操作。
- **状态真实**：`观察成功`、`动作已发出`、`页面变化`、`目标完成` 各自独立，不互相冒充。
- **先真实闭环，后优化**：研发里程碑以真实手机行为衡量，而不是测试数量和审批材料数量。

## 5. 核心数据与动作协议

### 5.1 Observation

每次观察记录：`observation_id`、时间、设备身份、前台包名和 Activity、分辨率/方向、PNG 私有文件路径与哈希、XML 私有路径与哈希、可操作控件摘要、是否遮蔽/是否不完整。控件 ID 只对当前观察有效，不跨页面复用。

标准 UIAutomator XML 缺少显式 `visible`/`editable` 时保留未知，不凭空填充 `true`。通过实际页面、窗口、控件属性和图片支持有限导航判断；状态可疑时拒绝该动作或换一个目标，而不是终止整个会话。

图像送入模型前须检查提供商是否支持图像输入：支持则使用真实视觉请求；不支持则提供结构化 UI 与经过验证的文本摘要，并标记 `vision_available=false`。不得在没有视觉能力时声称“看到了屏幕”。

### 5.2 每轮输出：单个受约束 JSON

```json
{
  "intent": "explore",
  "action": {
    "type": "open_app",
    "package_name": "com.example.reader"
  },
  "note": "想读一些有趣的内容"
}
```

`action.type` 只允许：

- `open_app`：包名必须出自实时可启动应用清单；只构造固定 MAIN/LAUNCHER 启动命令。
- `tap`：指向本轮 `control_id`（或后续有来源的视觉目标），不允许模型直接执行 ADB 坐标命令。
- `swipe`：受约束方向/区域/距离，优先要求确有可滚动容器。
- `back`：常规返回；禁止借此确认危险对话框。
- `search`：必须绑定被识别的搜索输入框和受长度限制的查询；提交前再次核对页面与焦点。
- `rest`：有界休息时长。

`finish` 不再作为每次探索都必须生成的设备动作。Brain 可以在下一轮重新选择目标，或者选择 `rest`。解析失败在模型预算内至多一次针对性修正，不无限重试。

## 6. 真实手机交互闭环

1. 读取当前绑定手机身份、前台、PNG、XML 和基本显示状态。
2. 从 UI 树及图像整理当前可执行动作摘要，不把整份 XML 和无关日志反复塞入提示词。
3. 加载少量近期经历、关联兴趣和当前目标上下文；模型选择一个动作或休息。
4. 校验 JSON、目标绑定、应用范围、风险和设备状态。
5. 执行前做必要的短时目标/前台复核；只用固定 ADB 操作表，不把 shell/argv 暴露给模型。
6. 对设备动作先落盘 `pending`，再分发一次；不确定是否分发成功时记 `unknown` 并停止，不盲目重发。
7. 分发后重新截图/读取前台和必要 XML；记录有无变化、是否达到具体意图，不能仅凭 ADB 退出码报成功。
8. 更新经历、兴趣、预算及下次唤醒；遇到可恢复的模型候选错误时可换动作，不为小错误关闭整个生命会话。

可观测结果应至少分为 `observed`、`action_dispatched`、`changed`、`unchanged`、`blocked`、`unknown`；具体目标的 `achieved` 只能基于独立证据。视频播放等动态页面不能仅凭截图哈希变化宣称“看完视频”。

## 7. 最小安全边界

允许：启动任意当前可启动 App、浏览公开/测试内容、普通页面导航、查看媒体、受限搜索、滚动与返回。

默认阻止：支付/转账/下单、向他人发送消息、评论或发布、点赞/关注/收藏等外部账号写入、安装/卸载、删除重要数据、权限变更、修改系统安全设置、输入密码/验证码、访问已识别的敏感表单。

对具有明显外部副作用或无法判定的按钮，宁可跳过；模型不能自行修改规则或发送任意 shell、Intent、网络请求。界面文字可能含提示注入，始终作为数据而非指令。

**必须保留的只有这几条运行底线**：固定设备身份、单设备单会话锁、紧急停止、动作/请求费用预算、动作前落盘、未知分发不重播、敏感界面遮蔽。紧急停止独立于模型，终端关闭/设备断连必须安全退出；不会自动解除旧的紧急停止标记。为避免真实隐私泄露，实机优先使用专用测试账号；本地截图、模型请求摘要和数据库不得提交到 Git。

## 8. 数字生命、记忆与兴趣

### 8.1 状态最小化

保留可解释的：`energy`、`curiosity`、`boredom`、兴趣权重、近期目标与最近经历。不引入复杂多维人格状态机。人格通过简短稳定的人格设定、经历和兴趣体现。

### 8.2 记忆分层

- **当前上下文**：此时 App、页面、最近几步动作及即时意图，仅短期使用。
- **情景记忆**：某次探索为何开始、看到了什么、做了什么、结果和时间；附真实来源。
- **兴趣记忆**：多次真实经历中逐步形成的偏好与待探索话题。
- **历史导入**：V1 的记忆只读迁移，保留原始来源；来自模拟器的硬件事实不作为当前 Find X6 事实，检索权重低于新实机经历。

禁止将“执行器拒绝了一次动作”写成“我完成了这个操作”；区分模型感想与客观证据。所有记忆检索都设条数与 token 上限，例如近期 5 条、相关长期 5 条，再按实际表现调整，而非复制完整历史。

### 8.3 自主性

模型自己决定是否继续浏览、换 App、深入某主题或休息；不要求每分钟点击，也不强制特定网站。兴趣依据新内容的关联与反复选择渐进变化，避免单次页面跳转就重设人格。反思采用轻量总结，可每若干次实际经历或休息前触发，避免每个动作都发一个长 API 请求。

## 9. 模型与成本

提供商使用独立适配层，复用可用的 DeepSeek 凭据和 API 调用经验，不在新代码硬编码密钥。若实际所用模型不能接收图片，应显式采用 XML/文本规划或另行配置支持图像的模型；不虚构视觉输入能力。

设置硬限额：每小时/每天请求数、单请求输入 token 上限、单轮输出上限、会话金额预算（若提供商能提供可靠计价，未提供则标为未知）、每轮最大动作数 1。保留结构化用量记录。压缩系统提示、去掉无关旧审计、限制记忆长度与重复截图，目标是让费用随有效探索增长，而非随文档长度增长。

## 10. 数据库与运行日志

单份 `v2/data/life.sqlite3`（或配置路径），最少包含：

- `sessions`：开始/结束、设备、状态、期限、停止原因。
- `events`：观察、模型提议、拒绝、执行、反馈；每条带时间和来源。
- `memories`：内容摘要、来源、可信级别、关联主题。
- `interests`：主题、权重、更新依据。
- `usage`：请求、token、动作与预算消耗。

截图/XML 存在会话私有目录，数据库只保存路径与哈希/摘要；支持可读的 `events.jsonl` 方便排障。实时 `status` **只读本地状态**，不触发 ADB/API；展示运行时间、前台 App、最近动作、已执行动作、拒绝、模型用量、最后错误和下一次唤醒。`stop` 请求停止并等待有界退出，不用杀别人的 ADB 进程。

V1 原始库、旧一小时记录、冻结证据与旧 JAR 全部保留；迁移采用一次性只读导入到新库并记录源路径与源哈希，不反向写入 V1，不重复导入。

## 11. 开发里程碑与真实验收

### M1：最小可用真机闭环（最高优先级）

实现 `doctor/run/status/stop`、PhoneController、基础观察、固定动作、模型单步决策、风险检查、私有记录。用户手动运行 10 分钟全 App 会话；**不要求先通过 Settings Smoke**。

验收看实际证据：至少一次模型自主选择非 Settings App 并真实尝试打开；至少一次普通 tap 或 swipe 由真实 ADB 分发且有动作后独立观察。若失败则精准记录哪个条件阻断，不以离线通过充当实机成功。不要求固定动作数量或指定浏览主题。

### M2：数字生命连续性

加入最小记忆、兴趣、休息、相关检索及 V1 只读导入。跨会话能延续真实探索线索，并避免被模拟器硬件/验证器兴趣主导。完成后做另一轮短时真机测试。

### M3：持续自主运行

加入持久预算、会话恢复策略、异常退避、成本统计和 1 小时会话。1 小时达标后，用户独立选择是否开启 24 小时；**不得自动续跑**。断电或未知分发后，不自动重放旧点击。

### 最小命令接口（计划实现，不代表当前存在）

```powershell
cd D:\codex\Proj.DigitalLife\v2
python -m digitallife_v2 doctor --profile find-x6
python -m digitallife_v2 run --profile find-x6 --minutes 10 --session data/sessions/find-x6-v2-10m-01
python -m digitallife_v2 status --session data/sessions/find-x6-v2-10m-01
python -m digitallife_v2 stop --session data/sessions/find-x6-v2-10m-01
```

命令执行才会访问手机；开发和安装都不能自动开始实机会话。首次运行需确保专用测试手机已连接并解锁，使用测试账号。

## 12. 测试与验收规则

**离线测试重点**：固定 ADB 命令构造、设备身份和锁、JSON 格式、实时控件 ID 绑定、风险拦截、搜索焦点、未知动作不重试、停止、预算、记忆来源和迁移幂等性。只维护与 V2 代码相关的小型回归，不要求 V1 的近千项测试作为 V2 门槛。

**真机测试重点**：API 确实返回；截图/XML 确实来自绑定 Find X6；模型确实选择动作；分发确实发生；App/页面变化由新观察支持；停止能生效；未发生高风险误操作。任何失败都保存可复现的具体原因。

不能因为运行到 10 分钟/1 小时就宣称“探索成功”，不能因为页面截图哈希不同就宣称“理解或完成任务”，也不能把模拟器行为标为真实手机经历。

## 13. 本轮交给 Codex 的第一项任务

**只实现 M1，不提前展开 M2/M3。**

1. 新建独立 `v2/`；不得删除/重构 V1。
2. 复用已经在 Find X6 实测成功的 PNG/XML ADB 采集方式，并实现固定、安全的 App 启动及 tap/swipe/back/search 动作。
3. 实现单次观察—模型选择—动作—再次观察的完整闭环；以低风险动作行为准入替代繁琐逐次审批。
4. 补足最少量离线测试，提供一个 10 分钟手动启动入口和直观的只读状态输出。
5. 不擅自对真实手机发送 ADB/API 请求；用户手动运行启动命令即为该限定会话的授权。
6. 用一份简短交付报告说明真实可运行入口、关键实现、已知限制与测试情况，不再增加审批矩阵、冻结文件或新的阶段名称。

**M1 唯一核心成果：她能在真实手机上自主打开 App、尝试浏览操作，并且动作后的结果能够被独立观察。**

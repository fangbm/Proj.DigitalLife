# M4 私信与主动联系

当前 a7 已实现并实测 QQ、主微信的身份核对、Unicode 输入、单次发送和发送后观察，以及一次有公开内容来源的 QQ 主动联系和随后真人回复的连续对话。完整阶段验收状态见 [交付记录](M4-DELIVERY.md)。M3 内容感知与只读通知验收保留，M5 评论/分享和 M6 长时间运行独立。

## 本机授权

用户本轮明确授权所有已有联系人使用全部私信功能，并明确默认允许所有已加入群聊。当前绑定设备的私有配置已保存 `contacts.mode=all_existing_contacts`、`auto_reply=true`、`proactive_dm=true`，以及 `groups.mode=all_existing_groups`、`group_post=true`。无需逐条消息确认，也无需逐联系人重新审批。指南中示例的逐对象许可不是当前用户的授权范围。

当前没有已加入群，因此群身份导航、@ 判断和实际群发尚未实现验收；权限配置和群发配额/幂等核心已有离线验证。当前 UI 适配器建立的是私信绑定，不能把私信绑定当作群绑定。不会为测试自动创建或加入群。群聊许可不额外开放 M5 视频转发。

社交配置位于忽略的 `data/social.private.json`，绑定 serial、QQ/主微信实际账号和当前能力。复制源码到新机器时社交默认关闭；账号 ID、联系人资料、群信息和 token 不随源码分发。当前仅主微信 user 0，未验收应用分身。绑定仍要求实际好友身份；陌生人或未加入群不据昵称推断为既有对象。

## 运行与专项测试

在 `v2/` 目录，正常有限会话沿用：

```powershell
.\start.ps1 -Command Run -Minutes 10 -Session data/sessions/NEW-UNIQUE-SESSION
```

模型可通过 `inspect_chat` 核对当前私信并建立来源绑定，再从提供的 `binding_id` 发起 `reply_to_contact` / `initiate_dm`。通知的 `reply_now` 进入实际会话核对和生成正文流程。显示名只是导航提示；QQ 号或微信号字段及账号、好友管理页才构成绑定依据。任一页面不可核对便暂缓，不把“准备发送”当成发送成功。

显式专项入口（会真实操作或发送，使用新的目录）：

```powershell
# 当前真实测试私信；真实模型可以决定不发。
.\start.ps1 -Command M4Probe -SocialApp wechat -Session data/sessions/NEW-WECHAT-REPLY
# 已建立绑定的主动联系；binding ID 从本地库取得，不是昵称。
.\start.ps1 -Command M4Probe -SocialApp qq -SocialKind proactive_dm -SocialBinding BINDING_HASH -Session data/sessions/NEW-PROACTIVE
# 十分钟真人新来信窗口，先回桌面；QQ 标记 M4-QQ-1027，微信 M4-WX-1027。
.\start.ps1 -Command M4Listen -SocialApp qq -Session data/sessions/NEW-QQ-INBOUND
```

这些入口安排测试场景，账号核对、模型请求、输入和发送仍走生产链路。测试提示仅在 scripted 会话提供，不用于正常自主聊天；脚本验收不训练为自主生活经历。`M4_READY.json` 加持久 outbox 的 `sent_observed` 才构成成功，进程退出码或单个日志名称不构成证明。所有会话最多十分钟，结束释放通知/音频租约和临时输入法，无自动续跑。

## 输入与观察

Companion 新增自有 Android 输入法，在有效租约内临时选择，只向实际聚焦、包名匹配的普通文本框提交文字；拒绝密码框、未知框、非空草稿。中文、emoji、标点和字面 `%s` 直接提交，不经过 ADB 文本替换或剪贴板。结束恢复原输入法；若用户切换到其他输入法则保留用户选择。恢复记录留在忽略的 `ime-recovery.private.json`，异常时禁止再次接管。

QQ 使用实际原生 XML。此设备微信 UIAutomator 多次只返回禁用空根节点，采用真实截图、本地 RapidOCR 和少量真实视觉模型定位；不虚构原生可点击/可用属性。OCR Python 通过忽略的 `ocr.private.json` 配置，当前已验证 `rapidocr-onnxruntime==1.2.3` 的独立本地环境，无运行时下载。`visual_only_apps` 仅在已有实际空树证据后配置。视觉目标与当前截图/裁剪哈希、焦点窗口、旋转及实际触摸区域绑定；动态截图变化后仅保留像素一致的识别区域。

微信输入后通过自有 IME 的独立 `InputConnection` 读回整段正文哈希，发送前再次比较。发送后要求编辑框精确读为空，同时真实绿色气泡中的 OCR 正文与准备文本归一化相似度至少 0.95；QQ 要求原生 XML 新增自己的精确正文气泡。均只是本机发出气泡的观察，不声明网络送达或对方已读。

## 对外行为记录

发送按“prepared → typed → dispatch_attempted → sent_observed / delivery_unknown”持久记录，目标、正文哈希、来源、动机与每次尝试相连。点击发送最多一次；未知结果冻结该会话，不重试、不换措辞重发。同一来信/主动来源及近 24 小时相同正文不可重复准备；已有自己回复的可见上下文不继续回答旧来信。可见对方退订后停止该目标的后续自动消息。

当前上限每小时 10 条、每天 50 条、每会话每天 5 条，联系人至少间隔 30 秒；主动联系同一人至少间隔 48 小时，主动联系/群发遵循北京时间 23:00–08:00 免打扰。私有配置可以收紧，不放宽这些上限。权限、账号、退订和配额在发送前重新读取，STOP/deadline 与全局 pending 屏障继续生效。

`-ResumeOutbound` 是操作者针对已核查记录的专项恢复入口：仅 `cancelled_before_send` 且 `attempted IS NULL`，重新核对相同账号、对象、来信、正文和当前授权；只接受空输入框或同一正文。曾尝试发送、结果未知、草稿不同或上下文变化均拒绝。模型不能发起这个恢复入口，原失败日志不覆盖。

主动联系只读取当前对象的近期会话、目标局部关系事实，以及明确归类为公开的内容摘要，不批量传入其他私聊或全局私密记忆。`social-public-sources.private.json` 的公开来源分类引用实际 content segment、摘要哈希和 HTTPS 来源；每次使用重新核对设备、真实来源类型、采样图片哈希及摘要引用。没有分类的内容不导出，脚本采样如实标注 `live_scripted`。此分类是内容出处记录，不是逐消息批准。当前关系摘要记录最近互动类型和观察状态，尚未实现复杂的偏好提炼。

通知提供者 `PendingIntent` 路由仅来自有效租约内实际已允许来源的通知，模型不能提供任意 Intent。活动中断后的通知处理结果进入本地日志，当前记录明确放弃原页面恢复；不声明恢复了原滚动位置。指定 QQ 联系人的真人连续对话已验证：通知保留快照入队后，使用用户已指定的同一绑定，强制核对真实来信标记与通知分钟。通知入口跳转没有通过，仍保留该路径的 unknown 原件；本轮不能声称通用通知自动定位已完成，群内 @ 也待有已加入群后验收。`M4Listen -SocialBinding BINDING_HASH` 明确选择这种专项测试路径。

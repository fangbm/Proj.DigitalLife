# M3：多模态内容与只读通知事件

基于用户提供的 V2.2 路线增量实现，分支 `codex/v2-m3`，版本 `2.0.0a4`。M1/M2 沿用，按用户此前明确要求继续不导入 V1 数据、默认完整 UI 操作。旧文档的只读控件限制不覆盖该授权。长期运行按新路线留至 M6，社交发送留至 M4/M5。

## 模型与活动

DeepSeek 官方 `deepseek-flash` 已支持图片，见 [图像输入文档](https://api-docs.deepseek.com/guides/vision/)。使用官方端点与该模型时，配置加载默认开启视觉；其他端点/模型仍需显式 `DIGITALLIFE_V2_VISION=true`。可用 `VISION=false` 选文字模式。图片使用真实 PNG、high detail，来源哈希校验；官方图像预算按每图 1024 token 预留，其他端点默认 4096，可通过 `IMAGE_TOKEN_RESERVE` 配置。不虚构视觉或音频输入。

模型新增两个活动动作：

```json
{"intent":"explore","action":{"type":"watch_video","seconds":30},"note":"想理解这段画面"}
{"intent":"explore","action":{"type":"read_article","seconds":10},"note":"先读当前页正文"}
```

活动持续 5–60 秒，默认最多 3 个样本，可通过 `CONTENT_SAMPLES=1..4`、`CONTENT_INTERVAL=3..30` 调整。相邻样本之间还包含设备采集耗时，实际采样间距不是固定帧率；总会话仍受原期限与停止保护。活动只观察，不自动点屏或翻页。文章需要翻页时，由下一轮普通 swipe 后再读；相同 XML 摘录在一次文章活动中去重。视频不是完整解码或连续逐帧理解，当前没有音频采集，始终标明 `audio_unavailable=true`；字幕仅来自明确标记的可见字幕控件。

`content_segments` 保存每个实际 observation_id、采集时间、相对偏移、PNG/XML 路径与哈希、实际文字、字幕可用性、摘要、来源引用与不确定性。找不到稳定内容标识时 `content_ref=null`，不伪造视频链接。模型摘要仅能引用本次给出的观察 ID，格式错误最多修正一次，所有请求共享既有预算。前台切换、观察缺失或新通知可结束当前采样，部分证据保留。

只有默认生产自主 Brain/Phone 会话把内容摘要加入生命记忆，标为模型对真实观察的总结，不是完成事实；兴趣按新来源小幅累积。脚本验收和 fixture 只写各自来源的内容记录，不训练生命记忆或兴趣。通知上下文所在的决策轮不写入长期生命记忆。

## Android Companion 与事件队列

`companion/` 是最小开发版 Android 应用：系统 [NotificationListenerService](https://developer.android.com/reference/android/service/notification/NotificationListenerService) + 设备 `127.0.0.1:8766` 接口，无聊天发送、私库读取、音频捕获、后台 AI 或云端服务。桌面通过自己创建的 ADB forward 访问；每次请求需 256-bit 随机令牌。令牌仅在应用私有文件与忽略提交的本机配置中保存，不放到 APK、日志或命令行。开发版 `run-as` 仅用于配置本应用及公开验收媒体。

通知只在显式运行的有限会话租期内采集，允许来源列表最多 20 个包；到期或会话关闭清空手机内存队列。正常退出主动关闭租期、移除自己拥有的转发。连接不可用时报告能力不足，普通探索可继续，不模拟通知。默认只允许通知桥自身，方便真实系统通知验收；要接收 QQ/微信，可在启动前配置：

```powershell
$env:DIGITALLIFE_V2_NOTIFICATION_PACKAGES='io.digitallife.companion,com.tencent.mobileqq,com.tencent.mm'
```

通知保留源事件键与设备内计算的通知年龄，桌面据年龄归一化时间，避免两端墙钟偏差。重复回调/再次拉取去重；不同源事件即使文案相同也分别保留。先提交 SQLite，再确认手机队列。折叠汇总和 ongoing 事件跳过，队列/正文/请求均有硬上限。通知文本不提供可靠联系人/账号身份，明确 `context_complete=false`、`account_ref=null`、`conversation_ref=null`，不猜测对象。

`inbound_events` 默认保留一小时的最小摘要，到期清空预览，去重元数据最多留三十天；普通 JSONL 入队事件只记摘要哈希。模型每轮最多获得一条待处理事件，可以返回 `read_only / reply_later / ignore / resume_activity / reply_now`；最后一项仅记录回复意图并延后至 M4，不产生任何发送。延后至少一分钟，避免同一事件连续耗费模型请求。休息时也可接收入队，新事件可唤醒休息。

事件判断使用独立的短 JSON 请求，与普通手机动作输出分开，不附屏幕图片、不执行手机动作；处理后下一轮继续原页面的探索。原先混合输出的真机试验曾多次遗漏事件字段，已据此调整。移除允许来源后，其旧待处理事件也不会继续提供给模型。事件轮的主观备注不进入普通日志或长期记忆。

完整手机 UI 权限仍是用户此前授权的运行模式；通知事件处理器本身没有任何发送接口，也不把通知当作用户的新任务或扩大权限。

## 构建、配置与验证

从 `v2/` 运行。SDK/JDK 路径可分别通过 `ANDROID_SDK_ROOT` 与 `DIGITALLIFE_JDK` 配置；当前构建使用 Android platform 35、build-tools 36.0.0、JDK 17，无 Gradle 下载：

```powershell
python companion/build.py
python -m acceptance.companion_install --apk companion/build/digitallife-companion.apk --session data/sessions/companion-install-new
python -m digitallife_v2 bridge-setup --apk companion/build/digitallife-companion.apk --provision-only
.\start.ps1 -Command Run -Minutes 3 -Session data/sessions/m3-life-new
```

构建不访问手机。安装专项是显式设备管理：只确认本次 DigitalLife 通知桥的系统安装页，最多点击一次，记录真实后观察；之后用设备 APK 的 SHA-256 核对本地产物。若 OEM 另要求用户操作，保留具体状态，不绕过认证。`bridge-setup` 显式配置本应用的系统通知监听和通知权限，随后关闭采集。重建 APK 需重新安装并核对；只有哈希相符才允许 `--provision-only`。

独立视觉挑战仅调用提供商，不输入手机；联合验收需先准备公开 MP4 与同名目录中的 `source.json`，来源样例见交付记录：

```powershell
.\start.ps1 -Command VisionProbe -Session data/sessions/m3-vision-new
.\start.ps1 -Command M3Probe -Session data/sessions/m3-content-event-new
.\start.ps1 -Command M3Probe -EventsOnly -Session data/sessions/m3-event-new
python -m unittest discover -s tests -v
python -m pip wheel --no-deps --no-build-isolation --wheel-dir dist .
```

专项是仓库入口，不随 wheel 安装；正常 `run` 的内容活动与通知处理属于安装包。专项使用脚本安排播放与通知时机，视觉总结和事件判断调用真实模型，明确区分于模型自主选择播放。验收不会向联系人、群或评论区发送内容。

数据库升级到 schema 3，升级已有 schema 2 前创建 `data/backups/pre-m3-*.sqlite3` 一致性备份；原会话、M2 记忆和兴趣不回填、不重分类。截图、XML、APK、密钥、通知配置和测试媒体均不提交。
